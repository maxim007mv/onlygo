# OnlyGo — AI-тревел-агент «О!дин запрос»

**Трек:** «О!дин запрос» · О!Хакатон Островок.

OnlyGo превращает **одно свободное сообщение** путешественника («хочу к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов») в готовую поездку: понимает явные и неявные требования, задаёт минимум уточнений, предлагает направления с аргументами, сравнивает отели/билеты/трансферы, объясняет выбор и риски, проверяет стыковки, ведёт до симулированной оплаты и умеет **инкрементально пересобирать** план при изменении условий.

## Быстрый старт

```bash
git clone <repo-url> onlygo
cd onlygo
cp .env.example .env        # опционально; без ключа LLM работает offline-режим
docker compose up --build
# открыть http://localhost:8080
```

Проверка: `curl -s localhost:8080/health` → `{"status":"ok"}`.

**Apple Silicon (M1/M2/M3):** базовый образ `python:3.12.8-slim-bookworm` мультиархитектурный и собирается нативно. Если нужна сборка именно под amd64 — раскомментируйте `platform: linux/amd64` в `docker-compose.yml`.

## Честность и «один запрос»

- Если направление и длительность понятны («в Сочи на 3 дня»), агент не останавливается на вопросе про даты: берёт ближайшие и пишет об этом.
- Неизвестный город («Париж») не подменяется молча: агент говорит, что его нет в демо-каталоге (данные синтетические).
- Если бюджет или лимит перелёта не выполнимы, это сказано прямо в ответе, с вариантами, что поменять.

## Демо-сценарий (1 клик)

- В UI: кнопка **«▶ Демо-сценарий»** в шапке или ссылка `http://localhost:8080/?demo=1`. Агент сам проходит весь путь с прогресс-баром:
  1. один запрос «хочу куда-нибудь к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов»;
  2. ответ на необязательное уточнение («ребёнку 5 лет»);
  3. пересборка «на 2 дня позже» (отель сохранён, билеты перепоисканы, Δ цены);
  4. пересборка «мы поедем с собакой» (смена направления на pet-friendly);
  5. исправление предупреждения о стыковке одной кнопкой (ночной обратный рейс → дневной);
  6. симулированная оплата;
  7. пост-покупка (ранний заезд).
- Из терминала (stdlib, без зависимостей): `python scripts/demo_e2e.py` (или `--url http://host:8080`) — печатает транскрипт и `DEMO OK`.

## Что улучшено во второй итерации

- **UI/UX**: карточки с ценой, звёздами, рейтингом, бейджами атрибутов (зелёные плюсы/красные минусы), полосой «% бюджета» и рангом; таймлайн поездки; проверки стыковок со сводкой ✓/⚠/⛔ и сортировкой по важности; корзина с позициями; правдоподобная форма оплаты (шаги, форматирование карты, обработка отказа); чипсы-примеры; бейдж режима; мобильная вёрстка с вкладками «Чат / План и корзина».
- **Объяснения с цифрами**: часы дороги из города вылета, температура моря/воздуха, доля бюджета, «без визы»; в карточке направления — какие ограничения (дети/питомец/виза/цена) учитывались при ранжировании.
- **Действенные предупреждения**: у каждого warn/error — кнопка конкретного исправления (например, «Взять дневной обратный рейс (13:30, 37 675 ₽)»), агент подбирает альтернативу из кандидатов и пересобирает план.
- **Пересборка**: ответ при правке не повторяет всё заново — «Пересобрал только затронутое», блок «Что изменилось» с Δ цены; объяснение направления повторяется только если оно сменилось.
- **Данные**: добавлены города вылета Краснодар, Нижний Новгород, Самара (итого 8).

## Интерфейс (в стиле Островка)
Дизайн повторяет визуальный язык Ostrovok.ru, но логотип, шрифт Spoof и фотографии не копируются:
- лаймовый hero `#acef81` с белым листом контента, скруглённым на 32px;

Как интерфейс ведёт пользователя:
- **Шаги** «1. Расскажите → 2. Направление → 3. Варианты → 4. План → 5. Оплата» продвигаются по ходу диалога.
- **Пустой экран** показывает 4 примера-запроса и короткую инструкцию «как пользоваться».
- **Подсказка после ответа агента** говорит, что делать дальше.
- **Иконки** — встроенный набор SVG в стиле Lucide (самолёт, отель, трансфер, метка, календарь, кошелёк и др.) вместо эмодзи-стикеров;
- **Карточки** с иконкой в цветной плашке, звёздами, рейтингом, ценой «от ₽», полосой «% бюджета» и раскрывающимся блоком «Почему этот вариант».
- **Таймлайн плана** с цветными проверками стыковок и синими кнопками «исправить».
- **Корзина** и форма оплаты в три шага.

Технически:
- Ванильный HTML/CSS/JS без сборки.
- Все клики обрабатываются через `data-act` и один делегированный обработчик, без inline `onclick`.
- Фокус-кольца, `aria-label`, тап-зоны от 44px.
- На мобильных — нижние вкладки «Диалог / План» и закреплённое поле ввода.

## Зависимости и переменные окружения

Ресурсы: ~150 МБ образ, <100 МБ RAM, сборка ~1 мин. Нужен только Docker (Compose v2.24+). Внешняя БД не нужна — SQLite-файл в volume `onlygo-data`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | любой OpenAI-совместимый endpoint (OpenAI, vLLM, Ollama, OpenRouter…) |
| `OPENAI_API_KEY` | пусто | ключ. **Пусто → offline-режим** |
| `OPENAI_MODEL` | `gpt-4o-mini` | модель |
| `APP_PORT` | `8080` | порт внутри контейнера |
| `DB_PATH` | `/data/onlygo.db` | путь к SQLite (сессии, профиль/память, брони) |
| `LOG_LEVEL` | `INFO` | уровень логов (stdout) |
| `APP_TZ` | `Europe/Moscow` | часовой пояс для «сегодня», дат оплаты и действий |
| `SESSION_TTL_DAYS` | `14` | сессии старше удаляются (брони и профили остаются) |
| `RATE_LIMIT_PER_MIN` | `120` | лимит запросов к `/api/*` с одного IP в минуту, `0` выключает |

**Два режима (виден бейджем в шапке UI и в `GET /api/config`):**
- **LLM** — если задан `OPENAI_API_KEY`: LLM извлекает требования (JSON-слоты + «неявные потребности») и пишет объяснение рекомендаций. Правила дополняют LLM (страховка от пропусков). Любая ошибка LLM → автоматический откат на правила.
- **offline demo** — без ключа: детерминированный rule-based агент (регулярки + слот-филлинг по-русски, шаблонные объяснения). Использует **те же инструменты** и выдаёт полноценный сценарий от запроса до оплаты. Это не заглушка: все тесты и метрики гоняются в этом режиме.

## Как это работает

```
сообщение → parse_request (LLM | rules) → merge в состояние сессии (delta)
          → неявные требования (с ребёнком ⇒ бесплатная отмена, «всё включено» ⇒ пляж …)
          → clarifying_questions (≤2, блокирующий только если без него нельзя: нет дат / нет вообще идей)
          → suggest_destinations → search_hotels → search_transport(туда/обратно) → search_transfers
          → assemble_trip (корзина + проверки стыковок + бюджет) → объяснение
правка    → rebuild: перезапускаются только инструменты, чьи входы изменились (↺ reused в трейсе)
checkout  → simulate_payment → пост-покупка (ранний заезд, перенос, напоминания, трансфер)
```

Покрытие этапов:
1. **Понимание и уточнение** — слоты: откуда/куда/страна, даты/месяц/длительность, бюджет или «недорого», взрослые/дети/возраст, питомец, лимит дороги, прямые рейсы, виза, поезд, питание, отмена, пляж/центр, «настроение» (тепло, море, горы, город, гастро, романтика…). Панель «Что я понял» показывает каждое условие и его источник (*явно / неявно / по умолчанию / из памяти*); крестиком условие можно убрать — план пересоберётся.
2. **Вдохновение** — скоринг 24 направлений: климат в месяц поездки (воздух/море/сезон дождей), время перелёта из города вылета, виза, детская/pet-friendly инфраструктура, оценка стоимости. В карточке: почему, компромиссы, риски.
3. **Подбор и сравнение** — по 3 отеля/рейса/поезда/трансфера с ранжированием под ЭТОГО пользователя (отмена, питание, пляж, детклуб, ночные вылеты, пересадки, багаж, животные), а не только по цене.
4. **Объяснение** — для каждого варианта «Почему подходит / Компромиссы / Риски», трейс вызовов инструментов («Логика агента»), редактируемые требования.
5. **Сборка и покупка** — единая корзина, проверки: прилёт→трансфер→заселение (ранний заезд), перенос даты заезда при прилёте после полуночи, ночной выезд к раннему рейсу, поздний выезд, животные, детское кресло, бюджет. Симулированная оплата (карта `4242…` — успех, `…0002` — отказ).
6. **Пересборка** — «на 2 дня позже», «бюджет меньше», «с собакой», «другой отель», «другое направление», «на 2 дня дольше»: меняется только затронутое, в чате блок «Что изменилось» (старое → новое, разница в цене).

Nice-to-have: пост-покупка (ранний заезд, поздний выезд, перенос дат, напоминания, привязка трансфера), **память между сессиями** (SQLite-профиль по `user_id` из localStorage: город вылета, питомец, питание, состав семьи), **метрики качества** (см. ниже), опциональные LLM.

## Данные / сидирование

- `app/data/*.json` — синтетические датасеты: 24 направления (координаты, климатические опорные точки, теги, ценовой уровень, kid/pet-score), 144 отеля, 72 варианта трансфера, 8 городов вылета. Генерируются детерминированно: `python scripts/generate_mock_data.py` (seed=42), файлы уже лежат в репозитории и загружаются при старте — сидирование не требуется.
- Рейсы и поезда генерируются на лету детерминированно (hash от маршрута+даты): длительность от расстояния, цена от расстояния×сезонности.
- Погода — модель на основе январских/июльских значений (mock, работает offline).

## Маршруты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | чат-UI |
| GET | `/health` | `{"status":"ok"}` |
| GET | `/api/config` | режим (llm/offline), модель |
| POST | `/api/chat` | `{message, session_id?, user_id?}` → ответ агента: reply, questions, requirements, candidates, plan, changes, trace, stats |

| GET | `/api/destinations` | mock-каталог направлений |

Пример:
```bash
curl -s localhost:8080/api/chat -H 'Content-Type: application/json' \

```

## Тесты и метрики

```bash
# в контейнере (ничего ставить не нужно)
docker compose exec app python tests/run_metrics.py
# против запущенного сервера / локально
python tests/run_metrics.py --url http://localhost:8080
# unit/e2e (локально): pip install -r requirements-dev.txt && pytest -q
# линтер и форматирование
ruff check . && ruff format --check .
# сквозной демо-сценарий против сервера
python scripts/demo_e2e.py
```

`tests/queries.json` — 10 диалогов (от «хочу отдохнуть» до точных дат). Метрики: **completion rate** (план собран + оплата прошла), **среднее число уточнений**, **ходов до первой рекомендации**, **time-to-first-recommendation**, **ошибки стыковок**, **попадание в ожидания** (море/лимит перелёта/направление), **успех пересборки** («на 2 дня позже» даёт новый план) и **доля частичной пересборки** (часть шагов переиспользована; при смене месяца честно пересчитывается всё).

Текущий результат (offline-режим):
```
completion_rate 1.0 · avg_clarifications 0.5 · avg_turns_to_first_rec 1.2
median_time_to_first_rec_ms ~8 · connection_errors_total 0 · expectation_hit_rate 1.0 · replan_success_rate 1.0 · replan_partial_reuse_rate 0.8
```

## Структура

```
app/main.py        FastAPI, маршруты
app/agent.py       оркестратор: понимание → уточнения → план → пересборка, трейс
app/parser.py      rule-based NLU (offline)
app/llm.py         OpenAI-совместимый клиент (env), fallback
app/tools.py       инструменты поиска: suggest_destinations, search_hotels, search_transport, search_transfers
app/trip.py        assemble_trip (сборка и проверки стыковок), simulate_payment
app/datastore.py   mock-данные, климат, генератор расписаний
app/db.py          SQLite: сессии, профили, брони
app/static/        UI (vanilla HTML/CSS/JS)
tests/             pytest + метрики
scripts/           генератор mock-данных
```
