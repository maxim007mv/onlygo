# CODE_AUDIT — анализ качества кода OnlyGo

Метод: чтение кода всех модулей и фаззинг API скриптом. Скрипт шлёт около 200 запросов: пустые, emoji, 5000 символов, `<script>`, битый JSON, чужие id, двойную оплату, параллельные запросы. Каждая найденная ошибка закреплена тестом в `tests/test_quality.py`.

## Что было не так и что исправлено

| # | Проблема | Влияние | Исправление |
|---|----------|---------|-------------|
| 1 | `/api/select` с неизвестным `kind`/`id` (отель «nope», направление «atlantis») падал с **500** (`StopIteration`/`TypeError` в `plan`) | падение при любой гонке UI или ручном вызове | `kind` — `Literal` (422); id проверяется по кандидатам/справочнику → `AgentInputError` → **400** |
| 2 | Даты вида «с 10.12 по 15.12», «3.01.2027» не распознавались, и агент задавал лишний блокирующий вопрос | хуже «одного запроса» | парсер `dd.mm[.yyyy]` и диапазонов, в том числе через Новый год; защита от «2.5 часа» и «150.000 ₽» |
| 3 | Даты в прошлом: «с 1 по 5 октября» 25.10 → 2026-10-01; «на Новый год» 30.12 → вчера | неверные билеты | `_future()`: дата без года — ближайшая будущая |
| 4 | Ответ LLM применялся без проверки (строки вместо чисел, несуществующее направление) | 500 при «плохом» JSON модели | `parser.sanitize()`: белый список слотов, типы, диапазоны (ночи 1–30, взрослые 1–9, дети 0–6, бюджет 5 тыс.–5 млн); применяется и к правилам |
| 5 | «На 90 дней дольше» → 97 ночей; `change_dates` с `value="abc"` → ValueError | 500 / абсурдные планы | ограничения `MAX_NIGHTS`; `value` валидируется (422), сдвиг ±30 |
| 6 | Повторная оплата (двойной клик) создавала второе бронирование | двойное «списание» | checkout идемпотентен по подписи плана (`duplicate: true`) |
| 7 | Гонка: параллельные запросы одной сессии (read-modify-write JSON) теряли изменения | потерянные правки | per-session `threading.Lock` в API |
| 8 | Бронирование сохранялось с `user_id=None`; `select`/`correct` затирали владельца сессии | не работала память/история | `save_session` с `COALESCE`, `db.session_user()`, индекс `bookings(user_id)` |
| 9 | Младенцы (0–1 год) считались как дети с тарифом 75% | завышенная цена | `child_fare_units()`: младенец — 10% тарифа |
| 10 | Группа больше вместимости машины получала цену одной машины | заниженная цена | число машин = ceil(люди / max_pax), отражено в минусах |
| 11 | Нет ограничений длины полей, `session_id` — любая строка | DoS/мусор в БД | `Field(max_length, pattern)`, пустое сообщение → 400 |
| 12 | Необработанные исключения отдавали HTML/стектрейс | утечка деталей | глобальные обработчики: 422/400/500 в JSON на русском, стектрейс только в лог |
| 13 | Неэкранированные `kind/id/slot/tool` в `onclick`/`innerHTML` | потенциальный XSS | `esc()` во всех вставках (id к тому же ограничены pattern) |
| 14 | Магические числа (7 ночей, 150000, 21 день, 14:00, +40 мин) | читаемость | именованные константы в `tools.py`/`agent.py` |
| 15 | Мёртвое условие `and not (... and False)` в `requirements_view`; неограниченный рост `history` | шум / рост состояния | удалено; `MAX_HISTORY = 40` |

Проверено и в порядке: стыковки (прилёт → трансфер → заселение, выезд → вылет) не дают ложных ошибок. Метрики не ухудшились: completion 1.0, 0 ошибок стыковок, медиана ~6 мс. Секретов в репозитории нет, `.env` в `.gitignore`. CORS не включён: UI и API на одном origin, это безопаснее, чем `*`.

## Что осталось (TODO)
- `agent.plan()` (~100 строк) стоит разбить на `_plan_destination/_hotels/_transport/_transfers`. Отложено, чтобы не ломать переиспользование трассы перед редизайном UI.
- Время рейсов считается в часовом поясе отправления (упрощение mock); нужны таймзоны.
- Не распознаются «2.5 часа» в ограничении перелёта и бюджет с точкой «150.000».
- Нет TTL/очистки старых сессий в SQLite; блокировки — в памяти процесса (при нескольких воркерах нужен Redis/`BEGIN IMMEDIATE`).
- `onclick`-строки в UI лучше заменить на `data-*` + делегирование событий (сделать при редизайне).
- Нет rate limiting и аутентификации (`user_id` из localStorage — прототип).
